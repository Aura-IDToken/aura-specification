## 3. Mandatory closure blockers

### DQ6-R1 — JCS-discriminating fixture

**Objective:** execute at least one fixture for which RFC 8785 differs from ordinary sorted/minified JSON serialization and record the independently generated bytes.

Minimum required evidence should exercise at least one genuinely discriminating rule, preferably more than one:

- UTF-16 code-unit property ordering involving supplementary-plane keys;
- ECMAScript number serialization (`-0`, exponent formatting, boundary values);
- rejection of non-finite numbers;
- JCS string escaping / raw UTF-8 behaviour.

The fixture MUST be executed independently by RI-PY and RI-RS. Expected values MUST NOT be used as a substitute for implementation execution.

**Closure condition:** the fixture demonstrates that both reference implementations execute RFC 8785 semantics, not merely the same degenerate CANONICAL-001 vector.

### DQ6-R2 — RI-RS boundary of record

Select exactly one RI-RS conformance boundary and document it as authoritative.

Required properties:

- JCS engine remains conformance-only;
- production `aura-guard` dependency graph is unchanged;
- exact dependency/version and lockfile are recorded;
- the authoritative adapter/test path is unique;
- competing RI-RS conformance implementations are marked SUPERSEDED or otherwise explicitly excluded.

**Closure condition:** one and only one RI-RS boundary is authoritative for DQ-006 conformance evidence.

### DQ6-R3 — Evidence reachability

The reference implementation evidence cited by the specification MUST become reachable from a default/reviewable branch or through an explicitly accepted immutable evidence publication mechanism.

Required repositories:

- `Aura-IDToken/aura-poc-a-core-v3.3`
- `Aura-IDToken/aura-guard-v1.3`

The evidence must remain traceable to the execution commits and must not be recreated or manually rewritten during promotion.

**Closure condition:** a clean checkout of each reference repository can locate the authoritative conformance adapter, test, and artifact evidence without relying on an unmerged ephemeral branch.

### DQ6-R4 — Governance ratification

After R1–R3 are proven, the Chief Architect reviews the complete evidence package and explicitly ratifies the transition:

```text
DQ-006 = OPEN → CLOSED / PASS
```

No implementation test may self-authorize this status transition.

The following are explicitly invalid closure evidence:

- equality against frozen constants without independent execution;
- using CANONICAL-001 alone to prove RFC 8785 semantics;
- copying RI-PY output into RI-RS evidence;

- declaring DQ-006 CLOSED before R1–R3 are satisfied;
